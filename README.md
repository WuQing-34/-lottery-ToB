# 🎡 幸运大转盘抽奖系统（CC / LP 双团队版）

一套可直接落地的抽奖系统：**两个团队各自独立的大转盘页面 + 统一管理后台 + Excel 库存导入/导出 + 钉钉群实时播报**。

## 双团队是怎么隔离的

两个团队共用一套程序、一个数据库，但所有数据都带 `team` 字段：

| 维度 | 隔离方式 |
| --- | --- |
| 奖品库存 | `prizes[].team`，两个团队各有一份独立库存 |
| 转盘奖品 | 按 `?team=` 计算，CC 的盘上不会出现 LP 的奖品 |
| 抽奖人 | `participants[].team`，同名的人可在两个团队分别存在、各自计数 |
| 抽奖次数 | 独立扣减，一方用完不影响另一方 |
| 中奖记录 | 按团队分开统计与导出 |
| 视觉 | CC 红金主题（`/cc`），LP 蓝金主题（`/lp`），一眼能区分 |

> 例：张三同时在 CC 和 LP 名单里。在 CC 抽完 1 次后 CC 显示「已抽奖」，但他在 LP 的 2 次机会完全不受影响。

## 现金抽奖（CC 专属，与实物独立）

`/cash` 是独立的现金奖池，紫金主题。与实物抽奖在数据层完全隔离：

| 维度 | 说明 |
| --- | --- |
| 奖池 | `cashPrizes` 独立库存，实物库存变化不影响现金 |
| 名单 / 次数 | `cashParticipants` 独立，实物名单不通用、次数不共享 |
| 记录 | `cashRecords` 独立展示与导出 |
| 概率 | 每个奖项自设「设置概率」，中奖只按概率决定；转盘扇区一律等分，面积与概率无关；系统自动换算「实际概率」 |

后台「④ 现金抽奖（CC）」可独立导入 Excel（奖项名称/金额/库存数量/每次发放/概率）、手动增删改、补货、加次数、导出库存表与记录、单独重置。概率为 0 的奖项永不命中；库存发完自动退出转盘；设置概率之和不必等于 100。

## 功能说明

### ① 库存管理（后台 → 库存管理）

- **按团队管理**：顶部切换 CC / LP，所有操作只作用于当前团队。
- **Excel 导入**：表头需含 `礼品名称`、`库存数量`、`每次发放数量`（顺序任意，支持同义词如"奖品/名称""库存/数量""每次/发放/单份"）。
  - 支持 `.xlsx / .xls / .csv`，拖拽或点击上传，导入前有解析预览。
  - 合并（同名更新库存）/ 覆盖（清空该团队后重建）两种模式。
- **库存导出 Excel**：一键导出真正的 `.xlsx`
  - 当前团队导出 → 1 个工作表（明细）
  - 全部团队导出 → 3 个工作表：`团队汇总` + CC 明细 + LP 明细
  - 列：序号 / 礼品名称 / 初始库存 / 已发放 / 剩余库存 / 每次发放数量 / 剩余可抽次数 / 状态 / 最近更新
- **实时看板**：初始库存、已发放、剩余、每次份数、剩余可抽次数、库存占比条、状态标签。
- 支持手动新增 / 补货 / 编辑 / 删除，改动通过 SSE 秒级同步到抽奖页。

### ② 抽奖人管理（后台 → 抽奖人管理）

- 添加：姓名 + 抽奖次数，保存即刻生效。
- 批量粘贴：每行 `姓名,次数`（次数可省略）。
- **同名重复添加 = 追加次数**，这正是"下次来抽必须先加次数"的实现。
- 状态：`可抽奖` / `已抽奖` / `未开始`，并显示已抽次数、剩余次数、最近抽奖时间。
- 只有名单里的人能抽，未登记会被拒绝并提示联系管理员。

> 闭环：管理员加「张三 2 次」→ 抽 2 次后状态「已抽奖」、剩余 0，再抽被拒 → 管理员「＋次数」→ 立刻可抽。

### ③ 大转盘抽奖页（/cc、/lp）

- Canvas 手绘：金色描边外圈、跑马灯、指针、中心按钮；CC 红金 / LP 蓝金两套配色。
- 抽奖前输入姓名校验名单，姓名本地记住，下次免输入。
- **抽完自动回到姓名填写页**：关闭中奖弹窗后自动清空当前人并弹出姓名输入框，下一位直接输入即可，不用点「换个人」；若此人还有剩余次数，输入框会预填他的姓名并提示，确认即可连抽。
- 转动时每过一格"咔哒"一声 + 指针回弹，停稳播中奖音效。
- 中奖弹窗：奖品名、发放份数、剩余次数、彩带粒子。
- 结果由服务端决定，前端只负责转到对应扇区（不可作弊）。
- 支持 `/cc?name=张三` 直接带入姓名（展台大屏固定投放）。
- 空格 / 回车快捷抽奖。

### ④ 钉钉群播报

每抽中一次发送文本（`[姓名]抽中[奖品][数量]份`）：

```
张三抽中AirPods Pro1份
张三抽中CC 冲锋衣2份
```

- Webhook 在「系统设置 → 钉钉群机器人」配置（已预置）。
- 支持加签（secret）；若用「自定义关键词」，关键词填 **抽中**。
- 可开启「@所有人」。
- 每条记录都记录推送结果，失败原因可悬停查看。
- 「发送测试消息」按钮可随时验证连通性。

### ⑤ 库存日报（每天自动推送）

每天 **18:30（北京时间）** 自动把两个团队的库存推到钉钉群，格式：

```
当前抽奖礼品库存如下：
↓CC团队↓
AirPods Pro已发放0，剩余库存3份，可抽3次；
机械键盘已发放0，剩余库存5份，可抽5次；
↓LP团队↓
27寸显示器已发放0，剩余库存2份，可抽2次；
```

- 后台「系统设置 → 库存日报」可改推送时间、开关、**预览文案**、**立即推送一次**。
- 按 **北京时间** 判断到点，与服务器时区无关（服务器是 UTC 也能准点发）。
- 当天已发过不会重复发；到点前后半小时内服务重启会自动补发；推送失败会在下一分钟重试。
- 发送结果记入「抽奖记录 → 操作日志」。

## 现金抽奖算法

1. 只保留有库存的现金奖项；按 `createdAt` 顺序生成扇区，**所有扇区面积相同（等分）**。
2. 中奖概率只取「设置概率」，按权重随机；概率为 0 不参与，全部为 0 时降级为均分。**中奖与扇区面积无关**——面积只是视觉呈现，概率才是唯一决定因素。
3. 命中后：库存 -= 每次发放份数，已发放 += 份数，现金次数 -1；服务端决定结果并同步指针落点。
4. 钉钉文案与实物一致：`[姓名]抽中[奖品][数量]份`。

---

## 抽奖算法（实物）

1. 所有「剩余库存 ≥ 每次发放数量」的奖品全部上转盘，数量不设上限，新增礼品即时显示；**扇区面积一律等分**，与概率无关。
2. 中奖只按每个礼品的「设置概率」决定：概率为 0 永不命中，概率和不必等于 100，系统换算成「实际概率」显示。
3. 兼容老数据：若所有礼品都没配置概率（全为 0），自动降级为按 `floor(剩余库存 / 每次发放数量)` 加权，行为与旧版一致。
4. 抽中后：库存 -= 每次发放数量，已发放 += 每次发放数量，该人已抽 +1。
5. 库存清零自动移出转盘；无库存时返回 `NO_STOCK` 且**不扣次数**。
6. 全程服务端执行，同名 1.5 秒防连点，写盘串行化，不会超发。

后台「① 库存管理」可为每个礼品设置概率（手动新增/编辑、Excel 的「概率」列均可）；库存导出含「设置概率 / 实际概率」两列。CC 与 LP 的概率各自独立。

## 部署到服务器（Ubuntu 24.04 · 8082 端口）

目标机：`YOUR_SERVER_IP`（`ubuntu` 用户，SSH 22），装到 `/opt/lottery`，跑在 **8082**。

**完整步骤请看 [DEPLOY.md](./DEPLOY.md)**（私钥获取、三种上传方式、防火墙放行、验证清单、故障排查）。

最省事的方式：双击 `deploy\一键部署.bat`，按提示输入私钥路径 → 回车 → 回车。

命令行方式：

```powershell
$KEY = "C:\Users\YOUR_USERNAME\Downloads\YOUR_KEY_ID.pem"
tar czf lottery-deploy.tar.gz --exclude=node_modules --exclude=.git --exclude=data --exclude=*.log .
scp -i $KEY lottery-deploy.tar.gz ubuntu@YOUR_SERVER_IP:/tmp/
ssh -i $KEY ubuntu@YOUR_SERVER_IP "sudo mkdir -p /opt/lottery && sudo tar xzf /tmp/lottery-deploy.tar.gz -C /opt/lottery && sudo chown -R ubuntu:ubuntu /opt/lottery && rm -f /tmp/lottery-deploy.tar.gz"
ssh -i $KEY ubuntu@YOUR_SERVER_IP "bash /opt/lottery/deploy/deploy.sh 8082 /opt/lottery"
```

常用运维命令：

```bash
sudo systemctl restart lottery      # 重启
sudo systemctl status lottery       # 状态
sudo journalctl -u lottery -f       # 实时日志
```

数据文件：`/opt/lottery/data/lottery-data.json`（复制即备份）。

> 一台服务器上放多个项目时，端口别撞：本项目默认 **8082**。
> 换端口：`bash deploy.sh 8083 /opt/lottery`，并到腾讯云轻量控制台「防火墙」放行对应 TCP 端口。

## 音效说明

爱给网（`https://www.aigei.com/item/chou_jiang_yin.html`）对当前环境做了 `banIp403` 拦截，
`www` / `m` / CDN 全返回验证页，代理出口也被拦，无法直接爬取。

系统内置了一套**纯 Python 数学合成**的音效（`scripts/gen_audio.py`），无版权风险：

| 文件 | 用途 |
| --- | --- |
| `tick.wav` | 转盘每过一格 |
| `win.wav` | 中奖庆祝 |
| `fail.wav` | 次数用完 / 库存不足 |

**换成爱给网原版**：把音频重命名为 `custom.mp3` 放进 `public/audio/`，刷新即自动优先加载，无需改代码。

## 常见问题

**Q：抽奖页显示"暂无奖品"？**
A：该团队礼品发完了，或还没导入。去后台切到对应团队补货 / 导入。

**Q：提示"不在抽奖名单中"？**
A：后台「抽奖人管理」里该团队没有这个姓名，或姓名不一致（会自动去首尾空格）。

**Q：两个人能不能同名？**
A：可以，但必须属于不同团队；同一团队内同名会被视为同一个人并累加次数。

**Q：钉钉没收到消息？**
A：看「抽奖记录」的推送状态，失败原因悬停可见（`errcode=310000` 通常是关键词或加签没配对）。

**Q：数据怎么备份 / 迁移？**
A：复制 `data/lottery-data.json` 即可。
